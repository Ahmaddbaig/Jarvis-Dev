# R02 typed Electron build

Status: implemented and verified on macOS arm64 on 2026-08-05.

## Source of truth

- Electron main and preload source live in `apps/desktop/src` and compile under strict TypeScript with `tsconfig.electron.json`.
- `dist-electron` is generated by `npm run build:electron` and is ignored by Git.
- The Computer Use helper is built from `scripts/computer_use.py` using the exact direct dependencies in `scripts/computer-use-requirements.txt`.
- `.build`, `.next`, `release`, `dist-electron`, and `scripts/dist` are generated outputs and are ignored by Git.

## Reproducible build flow

`npm run build` performs these stages in order:

1. Creates or reuses an isolated, platform-and-architecture-specific Python build environment under `.build` and produces a native PyInstaller executable.
2. Produces the Next.js standalone server.
3. Copies public/static assets and the current host's Computer Use helper into the standalone runtime.
4. Removes local settings, pairings, tokens, environment files, and root private-key files from the assembled runtime.
5. Compiles Electron main and preload from TypeScript, with source maps that include their TypeScript source.

Electron Builder packages the standalone server, Chrome extension, app icon, Electron output, and the two Electron runtime dependencies through explicit resource/file rules. Production dependencies used directly by Electron main are classified under `dependencies`.

## Verification evidence

- `npm run build`: pass; all 50 Next routes/pages generated.
- `npx electron-builder --mac --dir --publish never`: pass; unsigned arm64 `.app` created for local verification.
- Packaged Computer Use helper: Mach-O arm64.
- Packaged standalone server: started through the packaged Electron executable in Node mode.
- Smoke requests: `/`, `/api/settings`, and `/models/suit.stl` responded; unauthenticated `/api/chrome-control` was rejected with HTTP 403.
- Packaged local-state scan: no server settings, companion registry, desktop token, `.env` file, or root private-key file.

Windows and Linux helpers must be built on their native CI runners. Signing, notarization, installer recovery, and cross-platform smoke evidence remain release-gate work; this local directory build is not a distributable release.
